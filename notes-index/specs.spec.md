## General

This document descibes what is a good spec file.

## What is a spec
- a spec is just us describing what we want and why
    - no how we implemented it
    - one spec can describe multiple implementations
- a spec is not a tutorial or guide
    - it is not step-by-step instructions

## Good Specs Focus 
- include main concepts
- include key data structures
- include high-level architecture (how components relate)                                                  

## Avoid
- it avoid implementation details
    - an heuristic is, if it is easily visible in the code, it probably does not need to be in the spec

## What is NOT
- a spec is not a tutorial
    - avoid step-by-step instructions
    - avoid code examples unless they illustrate a key design decision
- What is NOT status or progress note
    - a spec is not a changelog
    - a spec is not a roadmap
